# 技术档案与面试准备

本文依据当前源码和实际职责材料整理。验证结果见 [VALIDATION](VALIDATION.md)；未来设计不当作已完成功能。

## 1. 架构和调用链

根qmake总工程组织server/shared/user/admin。shared为两个桌面程序复用网络和主题；server独立运行。桌面API客户端与手机JavaScript均访问HTTP/JSON服务，SQLite只由服务端访问。

主链：手机号格式校验/自动注册 → 查站点及电桩 → 预约 → 开始模拟充电 → 停止、计费和钱包扣款 → 订单记录。管理员通过另一套鉴权查看概览、维护设备/用户和查看订单。`server/router.cpp`承载业务，`server/database.cpp`定义schema和种子数据。

关键不变量是用户不能有多个活动订单、设备状态与预约/充电订单一致、服务端为计量和结算事实来源。界面只是显示和发起操作，不能代替服务端约束。

## 2. 原理与取舍

### qmake和公共层

`EVChargePlatform.pro`定义子工程依赖，`shared/shared.pro`生成公共静态库，user/admin链接。收益是构建入口单一与请求/主题复用；代价是绑定Qt工具链与正确输出顺序。没有为展示强加CMake或微服务抽象。

### Qt事件驱动HTTP

`HttpServer::incomingConnection`创建QTcpSocket，`consume`将readAll结果加入按socket保存的缓冲，先找CRLF头部边界，再等待Content-Length正文完整。readyRead驱动处理，disconnect清理缓冲并deleteLater。输入为TCP字节流，输出为ApiRequest和HTTP响应。

这是教学HTTP子集，不代表完整HTTP/1.1、TLS或高并发服务。现有1MiB正文限制不等于完整抗攻击措施；头部上限、严格长度解析、超时和压力测试仍是后续工作。

### 认证与API

`shared/apiclient.*`统一URL、JSON、认证头与异步响应。Router按方法/路径分发，`userId/adminId`检查内存token。手机号登录是演示身份选择，没有短信认证；重启使内存会话失效，没有生产级撤销/过期策略。

### SQLite与状态机

Database负责打开连接、建表、索引、种子与查询。SQLite便于单机交付，不意味着多节点并发写已验证。条件UPDATE与索引分别约束状态和活动订单。原有管理员操作能把reserved设回idle，已在临时数据库复现双预约；经明确授权增加reserved保护并做完整序列回归，不改变表结构。

### 模拟计量与可复现性

服务端按功率、经过时间和价格模拟计量，用户端每秒展示估算，最终以服务端结算为准。种子固定随机数但取当前日期；日期变化不等于算法回归。不能用演示营收和小时负载宣称真实设备采集或预测成果。

### 手机资源与PWA

HTML相对资源保留file预览；HTTP根入口需要精确资源别名。manifest start_url与Service Worker脚本作用域必须匹配部署目录。返回HTML不代表CSS/JS加载正确，静态资源成功也不代表普通HTTP手机环境能安装Service Worker。

## 3. 核心代码导读

| 文件/函数 | 输入输出 | 关键问题 |
|---|---|---|
| `server/main.cpp` | port/data/web → DB和监听 | 失败退出、路径、生命周期 |
| `HttpServer::consume` | socket字节 → 请求/响应 | 半包、长度、资源清理 |
| `Router::dispatch` | 方法/路径/token/JSON → ApiResponse | 权限、条件SQL、错误码 |
| `Database::initialize/seed` | 数据目录 → schema/模拟记录 | 索引、初始化与日期边界 |
| `shared/apiclient.cpp` | 请求参数 → 异步JSON响应 | 错误处理与UI解耦 |
| `user/userwindow.cpp` | 用户操作 → 请求/显示 | 找桩、地图切页、预约/充电 |
| `admin/adminwindow.cpp` | 管理操作 → 请求/图表 | 权限在服务端，显示不是状态事实 |
| `web/mobile/app.js` | 浏览器输入/定位 → 请求/DOM | sessionStorage、失败状态、静态预览 |

复习时用一次“预约→开始→停止”串起这些模块，而非逐行背诵。

## 4. 真实难点与排查

| 问题 | 原因与处理 | 仍有局限 |
|---|---|---|
| 根手机页无完整样式/行为 | URL基路径与文件位置不同，解析真实href/src请求复现，增加精确资源别名 | 还需真实移动端安装检查 |
| 最小Ubuntu缺GL/gl.h | Charts间接需要OpenGL开发头，真实构建后补libgl-dev | 其他系统未必相同 |
| 中文变方框 | 干净WSL缺中文字体，补fonts-noto-cjk并重截 | 字体渲染跨平台可能有差异 |
| 安装失败仍报成功 | 失败后继续printf，改为非零退出并验证失败路径 | 软件源网络故障仍需用户排查 |
| PRAGMA打印错误仍退出0 | 原脚本未判断输出，分别断言ok与无FK行 | 不覆盖所有业务不变量 |
| 测试请求误发已有服务 | 固定端口、未确认本次PID/监听，补归属与就绪检查 | 测试必须继续使用独立数据 |
| 同桩双预约 | 管理员覆盖reserved，新增条件保护和红绿回归 | 分布式多实例不在当前范围 |

这些是工程排查与修复，不包装成新算法。

## 5. 面试问题

| 问题 | 回答思路 | 项目例证 | 深入追问 |
|---|---|---|---|
| 基础：信号槽怎样支持网络？ | 事件循环回调，避免UI阻塞 | readyRead与ApiClient异步结果 | 慢连接/大量连接怎么处理？ |
| 架构：为什么客户端不直连DB？ | 集中权限和业务规则，多端共享契约 | Qt两端与手机复用Router | 多实例如何共享会话？ |
| 网络：一次read等于一请求吗？ | TCP是字节流，要按边界和长度缓冲 | consume保存半包 | chunked/非法长度/超时怎么补？ |
| 算法：附近站点如何找？ | 根据坐标计算距离并排序，是已有方法应用 | Router距离函数和用户端找桩 | 大数据量空间索引怎么设计？ |
| 代码：Qt对象如何释放？ | 父子对象及deleteLater，断开时清缓冲 | socket父为HttpServer | lambda捕获指针的寿命？ |
| 数据库：如何保持订单/桩一致？ | 列不变量，条件更新/事务/约束分工 | 活动订单索引与reserved保护 | 多进程检查再写的竞态？ |
| 数据：图表来自真实设备吗？ | 明确模拟种子和日期，不能冒充实测 | seed生成6站36桩 | 真实数据质量怎么校验？ |
| 计费：前端时间不同怎么办？ | 前端估算，服务端结算为准 | 功率×时间与钱包落库 | 幂等、断电、分时电价？ |
| 部署：为何Qt装了仍编译失败？ | 运行库与开发头不同，需真实构建 | libgl-dev依赖缺口 | CI/容器如何固定工具链？ |
| 测试：源码守卫算UI自动化吗？ | 不算，需与API和实际图形验证区分 | 27项源码守卫 | 稳定Qt交互测试怎么做？ |
| 性能：支持多少并发？ | 未压测不报数字，先定义延迟/吞吐指标 | 当前是功能测试和单机SQLite | 如何做可重复压测？ |
| 创新：个人技术价值在哪里？ | 解释公共层、HTTP、构建与联调，有证据 | 自己主责架构/公共层/集成 | 为什么不直接用成熟HTTP框架？ |
| 安全：演示登录能上线吗？ | 不能，需短信/密码策略/TLS/限流/会话控制 | 默认凭据、手机号选择身份 | 过期撤销、越权怎么验证？ |
| 改进：下一步优先做什么？ | 状态一致性/鉴权/设备协议优先，基于数据谈性能 | 先复现实际双预约再修复 | 如何制定可验收里程碑？ |

## 6. 贡献与科研拓展

李石屹负责组长、架构集成、qmake/shared/HTTP与构建链的复核完善；数据库和业务路由由其他成员主责。依据分工、个人总结及责任代码包，不把维护职责解释成每行代码的独立原创。面试优先讲能提供证据的接口、半包、依赖闭包与跨模块验证。

当前是工程系统，不宣称科研创新。可进一步研究：

- 状态机一致性：建立操作序列和故障注入，对比应用检查、条件更新、数据库约束的违规率与成本。
- 真实设备接入：在授权协议/数据上验证时钟漂移、缺包、重试幂等，避免用模拟量评价真实系统。
- 运营预测：当前没有模型，只有获得可靠数据后再做时间切分、基线、消融和跨站点泛化。
- 网络性能：先测延迟分位数、吞吐、资源，再比较线程/框架；不能凭代码结构宣称提升。
